# 响应式设计系统统一方案

## 背景

当前站点在桌面端呈现为扁平的极简技术刊物，移动端则混用了文档页面、流式展开菜单、浮动工具按钮和 App 风格底部抽屉。各组件单独可用，但布局轴线、文字层级、控件尺寸和表面造型缺少统一规则。

本阶段只统一视觉框架与响应式行为，不修改 `My Blog`、`Mingalaba`、`AstroPaper` 等品牌和首页示例文案。品牌内容在后续阶段单独确定。

## 设计方向

站点采用“开发者手记 / Code Notebook”方向：扁平、清晰、细边框、小圆角，用等宽字体和波浪下划线形成识别点。

- Google Sans Code 用于品牌、导航、标题、日期、标签和代码。
- 阅读正文使用系统 sans-serif，使英文正文更紧凑，并让中英文正文的阅读质感接近。
- 蓝色只承担链接、可操作图标、焦点和当前位置。
- 波浪下划线只用于主导航选中状态，装饰色使用 accent。
- 普通控件圆角不超过 `6px`，模态面板圆角不超过 `8px`。
- 页面主体保持扁平；只有真正覆盖内容的模态层可以使用克制的阴影和遮罩。

## 布局系统

### 普通页面

首页、文章列表、标签、归档和 About 的 Header、正文与 Footer 使用同一个 `max-w-3xl` 容器。桌面端品牌、正文和页脚建立共同的左边界；移动端继续使用 `16px` 页面边距。

### 文章页面

文章详情的 Header、主布局外框与 Footer 使用 `max-w-5xl`。正文和桌面 TOC 位于同一个网格中，正文保持适合阅读的宽度，TOC 占用固定辅助栏。

### 书籍页面

书籍页保留现有宽布局和侧栏，但 Header 与书籍主网格的外边界对齐，不强制套用普通页面的窄阅读容器。

## Header

### 桌面端

Header 分为品牌、主导航和工具组三部分：

```text
品牌    书籍 文章 标签 关于 归档    |    语言 搜索 主题
```

- 归档在所有视口都使用文字主导航，不再在桌面端显示为图标。
- 书籍、文章、标签、关于和归档使用相同的字体、间距和波浪下划线选中状态。
- 语言、搜索和主题组成工具组，图标保持 `24px`，点击区为 `32x32px`。
- 主导航与工具组通过间距和细分隔线区分，不使用卡片容器。

### 移动端

菜单按钮点击区为 `48x48px`。展开内容成为 Header 下方的覆盖面板，不参与正文布局，因此打开菜单时正文不发生垂直位移。

```text
品牌                         菜单
┌──────────────────────────────┐
│ 书籍          文章           │
│ 标签          关于           │
│ 归档                         │
│ 语言          搜索      主题 │
└──────────────────────────────┘
```

- 主导航使用两列、左对齐布局。
- 工具按钮位于独立一行，点击区统一为 `48x48px`。
- 面板使用背景色和上下细边框，不使用大圆角或重阴影。
- 菜单支持点击外部、选择链接和按 Escape 关闭，并维护 `aria-expanded`。
- 语言链接保留 `data-astro-reload`、`hreflang`、目标语言 tooltip 和无障碍名称。

## 文字层级

- 首页 Hero H1：移动端 `36/40px`，桌面端 `48/48px`。
- 文章标题 H1：移动端 `28/36px`，桌面端 `30/36px`。
- 正文 H2：`24/32px`。
- 正文 H3：`20/28px`。
- 列表文章标题：`18px`。
- 正文：`16px`，移动端行高不低于 `26px`。
- 移动端文章列表描述最多显示两行，桌面端显示完整描述。

文章标题必须始终比正文 H2 更突出。长标题可以自然换行，不通过 viewport 宽度动态缩放字号。

## 组件表面与状态

### 移动 TOC

- 底部面板顶部圆角由 `16px` 降为 `8px`。
- 降低阴影强度，使用顶部边框和遮罩表达层级。
- 选中项以 accent 左边线、强调文字和极轻底色表示，不使用大面积蓝色块。
- 列表缩进、字号和活动状态与桌面 TOC 保持一致。

### 浮动工具

- 移动目录和回到顶部按钮统一为 `44x44px`。
- 两者共享边框、`6px` 圆角、背景、焦点、hover 和 active 状态。
- 两个按钮使用同一个右下角垂直位置栈，动态显示时不互相覆盖，也不遮挡正文关键内容。

### 搜索模态框

- 搜索模态框与移动 TOC 共用表面 token：`8px` 最大圆角、同一边框颜色、同一遮罩和阴影强度。
- 搜索结果的 hover、选中和键盘焦点使用同一 accent 状态，不新增独立颜色语言。

## 保留行为

- 保留现有 locale URL、翻译 fallback、canonical 和 `hreflang` 逻辑。
- 保留 Astro 页面过渡；语言切换继续执行完整页面导航。
- 保留搜索、主题切换、TOC 高亮、回到顶部和移动菜单的现有功能。
- 保留当前颜色配置和明暗主题，不在本阶段更换品牌色。

## 不在范围内

- 不修改站点名称、首页 Hero 文案、社交账号或示例文章。
- 不新增图片、插画、动画或字体依赖。
- 不重新设计书籍信息架构、文章内容和桌面 TOC 功能。
- 不进行与视觉统一无关的组件重构。

## 验证

### 视觉与响应式

- 在 `390px`、`768px`、`1024px`、`1280px` 和 `1440px` 检查首页、文章列表、归档和文章详情。
- 检查中文、英文、明暗主题、长标题和原文 fallback 标签。
- 普通页面的 Header、正文和 Footer 在桌面端共享对齐轴线。
- 移动菜单展开时正文不位移，页面无横向溢出。
- 文章 H1 在所有断点都明显高于正文 H2。
- 所有移动触控目标不小于 `44x44px`。

### 功能与可访问性

- 验证菜单的按钮、外部点击、Escape、导航和焦点行为。
- 验证中英文切换不会重新出现标题缩放过渡。
- 验证搜索、移动 TOC、回到顶部、主题切换和主导航选中状态。
- 检查 tooltip、`aria-label`、`aria-current`、`aria-expanded` 和键盘焦点。

### 项目检查

按 CI 顺序执行：

1. `npm run lint`
2. `npm run format:check`
3. `npm run build`

三项全部通过后才算完成。
