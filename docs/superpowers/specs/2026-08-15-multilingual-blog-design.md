# 中英文博客支持设计

## 状态

已确认。本文档描述 AstroPaper 主题的中英文支持方案，目标是让主题可由使用者配置默认语言，同时保留静态博客的可索引性和清晰的内容语言边界。

## 目标

- 支持可配置的中文和英文站点。
- 使用默认语言无前缀、其他语言带前缀的静态路由。
- 让界面字符串、博客文章、书籍章节和独立页面分别具备翻译能力。
- 有译文时显示译文，没有译文时仍让用户访问原文，并明确标记原文语言。
- 保留现有默认语言 URL，避免破坏已有链接。
- 适配 GitHub Pages 等纯静态部署环境，不依赖运行时重写或浏览器语言检测。

## 非目标

- 本次不自动翻译现有文章、书籍或 About 正文。
- 本次只支持 `zh` 和 `en`，不建立任意语言的完整插件系统。
- 不根据浏览器语言自动跳转。
- 不在目标语言 URL 下复制没有译文的正文，避免重复页面和错误的 SEO 信号。

## 用户配置

沿用 `site.lang` 作为默认语言，并新增可选的语言列表配置：

```ts
site: {
  lang: "zh",
},
i18n: {
  locales: ["zh", "en"],
},
```

规则如下：

- `site.lang` 必须是启用语言之一。
- 默认语言不带 URL 前缀，其他启用语言使用自己的前缀。
- `site.lang: "zh"` 生成 `/` 和 `/en/`。
- `site.lang: "en"` 生成 `/` 和 `/zh/`。
- 只启用一个语言时不生成第二套页面，也不显示语言切换控件。
- 当前版本的界面字典只提供 `zh` 和 `en`，配置其他 locale 应在类型检查阶段被拒绝。

Astro 的 `i18n` 配置从同一份主题配置读取 `locales` 和 `site.lang`，避免构建路由与运行时语言状态分离。

## 路由架构

默认语言继续使用当前 `src/pages/` 下的页面，保持现有 URL。非默认语言使用带 locale 参数的共享路由入口，并调用相同的页面渲染组件：

```text
/                         默认语言首页
/posts/                   默认语言文章列表
/posts/<slug>/            默认语言文章
/en/                      英文首页（默认语言为 zh 时）
/en/posts/                英文文章列表
/en/posts/<slug>/         仅在英文译文存在时生成
```

页面渲染逻辑不复制两份。现有页面应拆出可接收 `locale` 和已解析内容的共享组件，根路径页面和 locale 路由页面只负责提供路由参数。

语言切换遵循以下规则：

- 当前页面存在对应语言版本时，切换到同一相对路径的目标语言页面。
- 当前页面不存在对应译文时，切换到目标语言的同类列表或首页。
- 不使用客户端 localStorage 或 cookie 决定页面语言。

## 内容组织

默认语言内容保留现有扁平结构，其他语言在对应 collection 下增加 locale 目录：

```text
src/data/blog/hello.md
src/data/blog/en/hello.md

src/data/pages/about.md
src/data/pages/en/about.md

src/data/books/astro-guide/index.md
src/data/books/en/astro-guide/index.md
```

内容语言通过文件路径推断：collection 根目录属于默认语言，首个匹配的 locale 目录属于该 locale。相同的 locale 相对路径默认视为同一翻译组。需要不同 slug 或跨目录配对时，collection schema 提供可选的 `translationKey` 覆盖推断结果。

内容解析需要提供以下能力：

- 取得内容的 locale。
- 取得不含 locale 目录的稳定相对路径。
- 根据 translation key 找到指定语言的译文。
- 在译文不存在时返回默认语言内容和其 locale。

博客、独立页面和书籍使用同一套翻译解析约定。书籍的 book slug、章节相对路径和 sidebar 构建必须先移除 locale 目录，再执行现有排序和分组逻辑。

## 缺少译文时的行为

采用 Kubernetes 文档站的“翻译优先、原文可达”模式：

- 有英文文章时，在 `/en/posts/<slug>/` 生成英文页面。
- 没有英文文章时，英文列表仍显示该文章，卡片标记 `(ZH)`，链接直接指向中文原始 URL。
- 有中文译文时，在中文列表中优先显示中文译文页面；没有中文译文时，对应英文内容标记 `(EN)` 并链接英文原始 URL。
- 不生成目标语言下仅包含原文的重复页面。
- 语言标记使用当前界面语言提供的可翻译字符串，而不是硬编码显示文本。

这种处理保证目标语言站点有可用内容，同时让用户知道正文语言没有被伪装成目标语言。

## 界面国际化

现有 `src/i18n/lang/zh.ts` 和 `src/i18n/lang/en.ts` 继续作为 UI 字典。需要新增语言选择和内容语言状态所需的字符串，例如：

- 选择语言。
- 中文 / English 的显示名称。
- 当前内容仅提供中文版本。
- 当前内容仅提供英文版本。

所有页面和组件从当前路由 locale 调用 `useTranslations(locale)`，不再直接使用 `config.site.lang`。`<html lang>`、`dir`、导航标签、分页、搜索、目录、书籍导航、无障碍标签、页脚和 404 页面都必须使用当前 locale。

Header 中加入语言选择控件。控件使用 `中文` / `English` 等明确语言名称，具备键盘焦点、可访问名称和移动端布局适配；只启用一种语言时不渲染。

## SEO 与元数据

- 每个页面的 `<html lang>` 与实际页面 locale 一致。
- canonical 指向当前页面的规范 URL。
- 有翻译关系的页面互相生成 `hreflang` alternate 链接。
- 没有译文的原文页面不生成目标语言 canonical 或目标语言副本。
- Sitemap 只包含实际生成的页面。
- fallback 卡片链接到原语言 URL，避免产生重复内容。

## 搜索与导航

- Pagefind 索引按实际生成的页面建立；fallback 卡片不创建重复的目标语言正文页面。
- 语言列表页可以展示 fallback 条目，但条目链接必须保留原语言路径。
- 文章上一篇 / 下一篇导航只在当前语言的译文集合中优先选择；缺少译文时可链接到原语言版本，但必须保留语言标记。
- 书籍 sidebar 只使用当前语言的章节集合，并对缺失章节链接到原语言章节。

## 错误处理

- 配置的默认语言不在 `locales` 中时，构建失败并给出明确错误。
- locale 不受支持时返回 404。
- 翻译 key 重复且指向多个同语言内容时，构建失败，避免随机选择内容。
- 缺少默认语言内容时保持现有 collection 的构建错误，不静默生成空页面。

## 验证

实现完成后按仓库 CI 顺序执行：

1. `npm run lint`
2. `npm run format:check`
3. `npm run build`

此外需要验证：

- 现有中文 URL 不变。
- 中英文首页、文章、书籍、About、标签、归档和搜索路由可生成。
- 未翻译内容在目标语言列表中显示语言标记并链接原文。
- 添加一个英文译文后，配对页面、语言切换和 `hreflang` 正确生成。
- 单语言配置不会生成或显示语言切换控件。
- 桌面和移动端 Header 不出现控件重叠或文字溢出。

## 迁移与兼容

- 现有默认语言内容无需移动目录。
- 现有中文链接和 markdown 文件路径保持不变。
- 使用者只需在需要翻译的内容 collection 下创建对应 locale 目录和同相对路径文件。
- 本次实现不要求现有内容补充 frontmatter；`translationKey` 只作为不同路径配对时的可选能力。
